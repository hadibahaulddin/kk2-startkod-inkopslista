# Kunskapskontroll 2 – Robust inköpslista

## Felrapport

### Fel 1
Så som du nämnt, så kraschade programmet direkt från början med ett IndexOutOfRangeExeption i Load(). Jag uppafattde att problemet låg i hur filen sparas och läses, att varje vara sparas på en egen rad som "pris;namn", och efter varje rad läggs en radbrytning, även efter den sista. Filen slutar alltså alltid med en tom rad. När programmet sedan läste in filen så delade det varje rad vid semikolonet, även den tomma raden längst ner. Eftersom den raden inte har något semikolon finns det ingen andra del att hämta namnet ifrån, och då kraschade programmet. Samtidigt delade Load() bara på en del av radbrytningen, så ett osynligt tecken (\r) hängde med i slutet av varje namn. För att lösa detta så bytte jag till File.ReadAllLines istället, min justering i koden gör att det delar upp filen i rader istället på rätt sätt utan att lämna kvar något skräptecken. Jag lade också till en kontroll som hoppar över rader som saknar antingen pris eller namn, så att en tom eller trasig rad inte längre kan få programmet att krascha.

### Fel 2
När programmet väl startade så visade det en totalsumma på 121 kr, men när jag räknade själv efter för hand så insåg jag att 15 + 32 + 89 = 136 kr. Skillnaden var exakt 15 kr, som är priset på mjölken, som ligger först i listan. Programmet kraschade inte, utan räknade bara fel, det var en bra luring av Tomas för att det är en lätt fel att missa. Problemet låg i for-loopen i Total(), som började på i = 1, men så som jag hittils vet så börjar C# listor på index 0, så den första varan ligger på items[0]. Eftersom loopen började ett steg för sent så hoppades den första varan alltid över och kom aldrig med i summan. Alltså min lösning var att ändra startvärdet från i = 1 till i = 0, så att loopen nu börjar från den första varan och räknar med alla varor i listan.

### Fel 3
När jag testade att skriva bokstäver eller bara tryckte ENTER trotsallt att programmet ville ha ett tal så  kraschade programmet direkt med ett FormatException. Felet fanns på tre ställen så som jag försot det, det var  i menyn, när man skriver in priset och när man väljer numret på en vara som ska tas bort. Problemet var att programmet använde int.Parse för att göra om texten till ett tal.Det får int.Parse att tro att texten alltid är ett giltigt tal, och om den inte är det så kastas ett undantag. Eftersom ingen del av koden fångade undantaget så kraschade hela programmet istället. Jag löste det genom att byta till int.TryParse på alla tre ställen. TryParse försöker göra om texten till ett tal, men istället för att krascha returnerar den false om det inte går. Då skriver programmet ut ett meddelande som förklarar vad användaren ska skriva, och med continue hoppar det tillbaka till menyn så att användaren kan försöka igen. Det är alltså 1 fel med samma orsak. 

### Fel 4 
När jag försökte ta bort en vara med ett nummer som inte fanns i listan, till exempel 7 så kraschade programmet igen med ett ArgumentOutOfRangeException. Användaren ser varorna numrerade från 1, så RemoveAt drar av ett från numret för att få rätt index i listan. Om man skriver 7 försöker programmet alltså ta bort varan på index 6, men listan har bara tre varor med index 0 till 2. Listan kastar då ut ett undantag eftersom platsen inte finns  och eftersom ingenting fångade undantaget kraschade hela programmet, det är som att kasta en boll men ingen fångar bollen. Jag löste det genom att lägga anropet till RemoveAt i ett try-block och fånga just ArgumentOutOfRangeException i ett catch-block. Istället för att krascha så skriver programmet istället nu ut ett meddelande om att det inte finns någon vara med det numret, och sedan visas menyn igen.

### Fel 5 
När jag döpte om items.txt och startade programmet igen sån kraschade det direkt med ett FileNotFoundException i Load(), detta var pågrund av att programmet utgick från att filen alltid finns, och försökte läsa den utan att först kontrollera det. Men första gången man kör programmet eller om filen har tagits bort eller flyttats så finns det ingen fil att läsa. File.ReadAllLines kastade ett undantag, och eftersom ingenting fångade det så kraschade hela programmet redan innan menyn visades. Jag löste det genom att lägga till en kontroll med File.Exists i början av Load(), så om filen inte finns så skriver programmet ut ett meddelande om att ingen sparad lista hittades, och avslutar sedan Load() med return. Alltså då böejar listan tom och programmet fortsätter som vanligt till menyn.
